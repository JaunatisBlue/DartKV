# DartKV Kitty 复现实验周期：论文要求对齐与 accuracy runner

## 目标与证据范围

本周期继续追踪用户目标“直到 Kitty 的实验结果可以复现”，参考文件是：

- `reference/paper-to-txt/Xia 等 - 2025 - Kitty Accurate and Efficient 2-bit KV Cache Quantization with Dynamic Channel-wise Precision Boost.txt`；
- `reference/code/Kitty/accuracy_simulation/`；
- `reference/code/Kitty/src/kitty_sim/`。

本轮完整阅读了论文文本（873 行、8454 词），并将论文的可复现实验拆成三层：

1. 算法语义：sink、Q/Local buffer、page/group、2-bit K/V、key channel promotion；
2. accuracy harness：lm-evaluation-harness、few-shot、task、seed、重复次数和
   K16V16/KIVI/Kitty 变体矩阵；
3. system benchmark：Qwen3-8B、约 100-token prompt、8192 generation、A100
   逐步增大 batch，记录 peak memory 与 tokens/s。

论文原始 accuracy 设置为 Qwen3（8B/14B/32B）、LLaMA3（8B/70B），任务包括
GSM8K、MATH-Algebra、HumanEval、GPQA-Diamond、AIME24/AIME25；Qwen3/LLaMA3-8B
使用 A100，较大模型使用 H100；FP16、2-bit KIVI、sink 变体与 12.5%/25% key
channel promotion 对照，生成上限一般为 4096，AIME 为 32768，实验重复 3--10 次。

## 发现的关键语义缺口

此前 DartKV 的 `hold_partial_pages=True` 只保留“最后不足一页”的 pending tail。
这与 Kitty simulation 不同：

- Kitty Key 在 Q-Buffer 满之前保留最新 `buffer_length` token；
- Kitty Value 在 KIVI-style 路径持续保留最新 `buffer_length` Local token；
- prefill 时即使总长度是 page 的整数倍，最新完整 buffer 也不能立即量化；
- page/group 默认 `G=buffer_length=128`，Key/Value 的量化分别沿 token/head-dim
  轴执行，sink 默认 32。

如果仍按旧行为把 prefill 最新完整 page 量化，短上下文和首次 decode 的模型输出
会与 Kitty simulation 偏离，不能声称复现论文准确率。

## 本轮代码修改

### `DartKVCacheConfig.local_tokens`

新增非负配置 `local_tokens`，默认 0 以保持已有 Dart reference 行为。设置为
`page_size` 时，`_append_remainder()` 的量化边界改为：

```text
available = max(total_pending_plus_new - local_tokens, 0)
full_tokens = floor(available / page_size) * page_size
```

因此只量化 Local/Q suffix 之前的完整 page，pending dense segment 可以暂时大于
一个 page，直到后续 token 使更早部分凑满 page。默认 `local_tokens=0` 不改变旧的
不足一页 pending 逻辑。

### `examples/run_qwen3.py`

增加 `--local-tokens` 参数，允许已有本地 Qwen smoke runner 显式复现 Kitty 的
dense suffix 语义。

### `examples/reproduce_kitty.py`

新增统一 accuracy runner，变体映射：

| runner variant | Kitty 对照 | Dart 配置 |
| --- | --- | --- |
| `fp16` | K16V16 | Transformers `DynamicCache` |
| `kivi-2` | KIVI-K2V2 | K/V 2-bit，sink=0，promotion=0 |
| `kivi-2-sink` | KIVI-K2V2* | K/V 2-bit，sink=32，promotion=0 |
| `kitty` | Kitty | K/V 2-bit，sink=32，key promotion=12.5% |
| `kitty-pro` | Kitty-Pro | K/V 2-bit，sink=32，key promotion=25% |

runner 使用本地 `lm_eval.simple_evaluate` 与 Qwen/LLaMA Transformers model，记录
model/task/variant/seed/dtype/device/cache config、每次 repeat 的 results/samples，
输出至 `results/kitty_repro/<model>/<task>/`。`local_tokens=buffer_length` 已固定
用于所有 Dart 变体；`--limit 1` 可先完成 smoke，再放大到论文完整 task。

## 本周期验证

### 单元测试

新增 `local_tokens` 生命周期测试：

```text
13 cache tests passed
27 repository tests passed（local_tokens 修改前的完整套件）
```

测试验证 13-token、page=4、local=4 的 page 顺序为 `Q,Q,D(5)`，追加 3 token
后变为 `Q,Q,Q,D(4)`，并保持恢复 shape 正确。

### Kitty reference 对照 smoke

命令使用同一进程、同一 Qwen3-0.6B、同一 FP16 模型和同一 seed，分别运行 Kitty
reference `KittyKVCache` 与 Dart `DartHFCache`：

```text
model: /opt/model/Qwen/Qwen3-0.6B
prompt: Explain why a key value cache helps autoregressive decoding in two concise sentences.
sink: 2, buffer/page/group: 8, kbits=vbits=2, promote=25%, channel=magnitude
seed: 20260823, max_new_tokens: 4
```

两条路径产生完全相同的 token ID：

```text
[840, 20772, 3170, 264, 1376, 897, 6500, 8609, 3078, 460,
 46719, 47116, 304, 1378, 63594, 22870, 13, 7281, 11, 10339, 3170]
```

Dart cache 在该 smoke 结束时为 `1,763,328 bytes`，等价 dense cache 为
`2,293,760 bytes`，压缩比 `1.30×`。这证明 local suffix 和 generation adapter
已能在小模型、小 page 配置下对齐 Kitty 行为；不把它误报为论文 8B accuracy。

### lm-eval accuracy runner smoke

命令：

```bash
CUDA_VISIBLE_DEVICES=0 conda run --no-capture-output -n dartkv \
  python examples/reproduce_kitty.py \
  --model /opt/model/Qwen/Qwen3-0.6B --task gsm8k_cot_llama \
  --variant kitty-pro --device cuda:0 --dtype fp16 \
  --limit 1 --repeats 1 --max-new-tokens 64 \
  --output results/kitty_repro
```

结果文件：
`results/kitty_repro/Qwen3-0.6B/gsm8k_cot_llama/kitty-pro_summary.json`。
该 smoke 成功完成 lm-eval task，记录 `torch=2.7.1+cu126`、Python 3.10.20、
A100 `cuda:0`，并返回一个合法的 exact-match 结果（0/1 样本）。同一 task 的
FP16 variant 也成功完成；0.6B 模型准确率不能与论文 8B 表格直接比较。

需要注意：lm-eval 会 deepcopy generation kwargs 中的 cache，使每个请求拥有
独立 cache；因此 accuracy runner 不从外层 cache 对象读取 storage bytes，而把
配置与结果样本作为准确率证据。系统 memory/throughput 应使用独立的连续 batch
benchmark，不应混用该 harness 的 request-level cache 副本。
