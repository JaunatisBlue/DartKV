## 本周期完成内容

### 1. 安装论文版本 FlashAttention

- 在 `dartkv` 环境安装 `flash-attn==2.7.4.post1` 和 `einops==0.8.2`；
- 使用 `/usr/local/cuda-12.9` 的 `nvcc`，设置 `CUDA_HOME=/usr/local/cuda`；
- 发现该版本构建脚本读取的是 `FLASH_ATTN_CUDA_ARCHS` 而不是 `TORCH_CUDA_ARCH_LIST`，
  最终以 `FLASH_ATTN_CUDA_ARCHS=80 MAX_JOBS=4` 只编译 A100 `sm80`，避免无意义的
  `sm90/sm100/sm120` 编译；
- 当前组合为 Python 3.10.20、PyTorch 2.7.1+cu126、CUDA runtime 12.6、FlashAttention
  2.7.4.post1。论文环境仍是 PyTorch 2.4.1/CUDA 12.1，差异保留在结果元数据中。

### 2. 补齐 Kitty 官方工具链

已将 `reference/code/Kitty` 以 editable 方式安装，并安装 README 中列出的工具：

- `kitty==1.0.0`（本地 editable）、`triton==3.3.1`；
- `matplotlib==3.10.9`、`seaborn==0.13.2`；

- `ninja==1.13.0`（FlashAttention/CUDA 和 Triton 构建辅助）；

`kitty_sim`、`kitty.kvcache`、`kitty_sim.eval.runner`、`hqq`、`flash_attn` 均已成功导入。
对应安装命令、版本和 A100 构建变量已经写入 `README.md`、`requirements-eval.txt` 和
`requirements-lock.txt`。

### 3. 三层运行验证

- `flash_attn.flash_attn_func` 在 GPU0 上对 FP16 `[1,16,8,128]` Q/K/V 实际执行成功，
  输出 shape/dtype 正确且全部有限；
- Qwen3-8B 使用 Transformers `attn_implementation="flash_attention_2"` 完成 GPU 前向，
  logits shape 为 `(1, 9, 151936)` 且无 NaN/Inf；
- Kitty prompt、chat template、`batch=1`、`max_seq=1400`、一次 warmup/一次 repeat 下：
  FlashAttention dense baseline 为 21.36 token/s，Kitty 官方 Triton engine 为 17.04 token/s，
  当前短序列 engine/dense 吞吐比约 0.80，同时 Kitty KV storage 约 3.13x 压缩。
  两者生成 token 前缀一致，说明新环境没有破坏协议。

## 当前判断

FlashAttention 和 Kitty 官方依赖已经在本机真正可执行，不再是“仅写入 requirements”。
Kitty engine 在短序列 `max_seq=1400` 下相对 FlashAttention dense 的吞吐约 80%，但显存/缓存
存储优势已出现；论文 Figure 5 的长上下文、批量增长场景仍需实测，不能用短序列结果替代论文
加速比。Dart 当前 packed cache 仍是正确性优先路径，不能宣称已达到 Kitty fused kernel 的
吞吐，后续必须以官方 engine 和长上下文 batch sweep 为验收基准。
