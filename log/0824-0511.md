# 第四轮阶段记录：Figure 5 端点复现与 Kitty 完整依赖

时间：2026-08-24 05:11（Asia/Shanghai）

## 上一步概述

上一周期已经把 Figure 5 的性能协议分成论文模式与 artifact 模式：论文模式使用精确 100
token prompt、总序列长度 8192，artifact 模式保留官方脚本实际产生的 1179-token prompt；同时
对齐了 Kitty 官方 engine 的 FlashAttention 2 prefill，并用短序列 profiler 确认 Kitty decode
kernel 已实际执行。本周期的目标是跑到两种实现各自的最大 batch，直接检验论文的 8 倍 batch
和 2.1--4.1 倍吞吐结论。

## 本周期完成内容

### 1. Figure 5 最大 batch 端点

固定 Qwen3-8B、单张 A100 80GB、FP16、FlashAttention 2、100-token prompt、总长度 8192、
warmup 1、repeat 1，得到：

| 实现 | 最大成功 batch | 完整序列 tok/s | 生成 tok/s | 计时轮耗时 |
| --- | ---: | ---: | ---: | ---: |
| HF Dynamic FP16 | 32 | 314.28 | 310.45 | 834.10 s |
| Kitty engine | 256 | 1579.93 | 1560.64 | 1327.37 s |

端点 batch 增益为精确 **8×**，吞吐增益为 **5.03×**。论文报告的吞吐增益区间为
2.1--4.1×；本机结果没有低于目标，而是比论文区间上限高 22.6%。Kitty batch256 的实测
KV storage 为 57.39 GB，对应 dense KV 309.24 GB，压缩比 5.39×。

边界也已用真实失败验证：Kitty batch512 在静态 KV cache 分配时 OOM；HF Dynamic FP16
batch64 在 warmup 的 `DynamicCache.update()` 拼接 key cache 时 OOM。因此 256 与 32 确实
分别是当前协议下的最大 batch，不是人为截断的 sweep 端点。机器可读结果写入
`experiments/kitty_figure5_reproduction.json`。

### 2. 官方依赖补齐

当前环境已安装并验证 Kitty 1.0.0、FlashAttention 2.7.4.post1、Triton 3.3.1、HQQ、
Optimum-Quanto、lm-eval、matplotlib、seaborn、einops 和 ninja。进一步对照 Kitty 容器定义时
发现官方还要求 `lm-eval[math]`，现已补装并锁定：

- antlr4-python3-runtime 4.11.0；
- latex2sympy2-extended 1.11.0；
- math-verify 0.9.0。

`pip check` 与三个新增模块的 import 均通过，后续 MATH/AIME 不再缺数学解析依赖。

### 3. 计时和显存口径修正

性能脚本现在对所有 cache 显式传入 `disable_compile=True`，与官方脚本一致；结果同时记录
`max_memory_allocated` 和 `max_memory_reserved`，避免 DynamicCache 的 allocator reservation 与
碎片只在 nvidia-smi 中可见。旧端点运行时已现场观察到 Dense batch32 约 73.8 GiB、Kitty
batch256 约 74.5 GiB，属于同显存比较。

### 4. 第一项完整精度结果

GPU1 完成了 Qwen3-8B / GSM8K / Kitty-Pro / paper 协议的全部 1319 个样本，单 seed strict
exact match 为 **93.63%**；论文三次均值为 **94.34% ± 0.48**。单次低 0.71 个百分点，超出
当前按论文最大偏差设置的 0.48-point 验收线，所以尚不能宣称 Table 3 精度复现。已利用现有
repeat 0 checkpoint 启动 repeat 1、2，最终按三次均值判断。

## 当前判断
