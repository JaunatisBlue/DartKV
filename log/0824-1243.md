## 本阶段功能审计与修复

### 1. Random channel selection

Kitty 的 `build_promote_mask` 支持 Random（每个 KV head 一个 `torch.randperm`，batch 内共享
选择），而 DartKV 原先只允许 magnitude/variance，Figure 4 random 分支会被拒绝。现在已补齐
random 策略，并移除 Dart backend 的拒绝逻辑。

### 2. K/V 不同量化边界

Kitty KIVI-style Value cache 按 token 量化，Key cache 按 page 量化，导致两边 segment 数量和
边界天然不同。旧 `iter_segments()` 强制 K/V segment 数相等，跨 page decode 会报错。现在：

- Value 的 token-wise packed tensors 按 page 增量合并，保留每 token 的 scale/zero-point；
- K/V 仍允许不同边界，streaming/fused attention 按逻辑 union 边界对齐；
- 只有边界切片 materialize，不再复制完整历史 cache；
- CPU 193-token 差分跨越多个 page 全部与 Kitty simulation exact equal。

### 3. Qwen3 model integration

新增 `DartQwen3Attention` 和 `attach_dart_fused_attention`：

- prefill 使用传入的 FlashAttention 2/eager backend；
- decode 的单 token 直接从 Dart packed pages 调 `fused_dart_attention`；
- HF generation 的 `dart_fused_attention` cache 生命周期避免每步 materialize 完整 K/V；
- benchmark 新增 `--cache dart-engine`，与官方 `--cache kitty-engine` 明确区分。

唯一目标模型 Qwen3-8B 已完成跨 page CUDA smoke（prompt100、max_seq_len256、warmup1/repeat1）：
输出长度正确，packed cache storage 23.80 MB，峰值 allocated 16.42 GB、reserved 16.65 GB，
没有 dtype、page boundary 或 Triton kernel 错误。45 项测试全部通过。

### 4. 运行监控口径

后续 GPU 监控同时记录显存、`utilization.gpu` 百分数和 `power.draw` 瓦特；百分数不再解释为
功耗。实验结果的显存验收以 `max_memory_allocated`/`max_memory_reserved` 为主。

## 当前判断

Kitty 的算法生命周期、Random selection、K/V page 对齐和 Qwen3 fused decode 已具备可执行代码
路径。Dart engine 短 8B smoke 的 generated throughput 约 6.1 tok/s（max_seq_len256、batch1），
仍明显低于官方 Kitty engine 的同协议短点；差距主要来自 Python page orchestration 与每步
量化，而不是功能缺失。因此不能把官方 Kitty engine 的 Figure 5 数字冒充 Dart engine 的
结果，下一轮需要在功能验收通过后单独测两条实现并优化速度。
