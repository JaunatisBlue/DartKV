# DartKV 第二阶段完成记录与第三阶段建议

## 本轮完成内容

本轮工作依据 `log/0823-1520.md` 展开，主要完成了真实模型接入和 PyTorch 参考路径。代码仍然保持 Dart 命名，不复制 Kitty 的模型实现或 Triton kernel。

### 量化与 cache

- `quantize` 增加了显式 `axis` 支持，能够在保持原始布局的情况下沿 token 或 head dimension 分组；
- key 和 value 现在使用不同量化语义：key 沿 sequence/token 轴分组，value 沿 `head_dim` 轴分组；
- 增加 `MixedQuantizedKey`，普通 key channel 保存低 2-bit，选中的 channel 额外保存 4-bit 高位和 channel index；
- 增加 magnitude/variance 两种 key channel 选择策略，并保证固定输入时选择确定；
- `DartKVCacheConfig` 增加独立的 key/value bit width、group size、page size、sink token、partial-page buffer、promotion ratio 和 channel selection 配置；
- cache 支持 page-sized quantization，`hold_partial_pages` 开启时将不完整 page 保留为 pending buffer，下一次 update 时再 flush；
- 增加了 `DartHFCache`，通过 Transformers 公共 `Cache` 接口接入模型，并支持 cache length、beam reorder、实际 packed storage 统计和 dense bytes 对照。

### Qwen3 模型基线

- 安装并锁定 `transformers==4.53.2`、`safetensors==0.8.0` 和 `accelerate==1.14.0`；
- 使用本机 `/opt/model/Qwen/Qwen-8B`，模型配置为 Qwen3、36 层、32 query heads、8 KV heads、head_dim 128；
- 新增 `examples/run_qwen3.py`，支持本地 tokenizer、dense DynamicCache、DartHFCache、固定 seed、BF16/FP16、eager/SDPA、prefill/decode timing、CUDA peak memory 和 JSON 结果输出；
- 结果默认写入 `results/qwen3`，该目录被 `.gitignore` 忽略，不会提交模型输出或临时数据。

### Qwen3-8B 单卡对照

实验条件固定为：`cuda:0`、BF16、eager attention、seed `20260823`、prompt 为“Give a concise definition of a key-value cache.”、生成 4 个新 token。模型本地 Hugging Face cache tree 的 revision 为 `b968826d9c46dd6066d109eabc6255188de91218`。

| 配置 | prefill | decode/token | cache bytes | 压缩比 | 输出 |
| --- | ---: | ---: | ---: | ---: | --- |
| dense FP16/BF16 | 573.95 ms | 52.26 ms | 1,916,928 | 1.00× | `A key-value cache` |
| Dart uniform K2V2 | 738.58 ms | 88.71 ms | 1,050,624 | 1.82× | `A key-value cache` |
| Dart mixed K2V2 + promoted K4 | 822.09 ms | 96.34 ms | 1,105,920 | 1.73× | `A key-value cache` |

上述 cache bytes 是实际 packed values、metadata、indices 和 sink/buffer 的 tensor storage。Dart 结果的 attention 仍然使用物化后的 dense K/V，因此这里的延迟不能解释为性能加速；量化和物化本身也包含在参考路径中。完整命令和 peak memory 记录见 `docs/EXPERIMENTS.md` 及 `results/qwen3/*.json`。

## 尚未完成的部分

本轮达成的是正确性和生命周期参考路径，不是最终系统：

1. 尚未把解量化融合进 attention，当前模型 attention 前仍会产生 dense K/V 临时张量；
2. 尚未实现 Triton/CUDA page packing、dequantization attention 或真正的低显存 decode kernel；
3. 已用官方 `lm-eval==0.4.12` 完成一条 `hellaswag --limit 1` dense smoke check（acc/acc_norm 均为 0）；这只是 harness 集成验证，不是可发表的标准任务分数，尚未完成完整 validation split 或 Dart cache 的 harness adapter；
4. 尚未完成长上下文、多 prompt、多 batch、beam search 和双 A100 的系统评测；
5. promotion 参考表示目前固定为低 2-bit + 高 4-bit，尚不支持其他高位布局；
6. 当前 page buffer 只保证 PyTorch reference 生命周期，不提供并发请求或生产级分页调度。

## 第三阶段建议

第三阶段应以 profiling 结果为依据，优先完成以下工作：

1. 先建立长上下文、固定 prompt 集和标准任务的评测 harness，保存 logits/生成文本、有效样本、峰值显存和原始 JSON；
2. 对 quantize、pack、unpack、dequantize、materialize 和 attention 分别 profile，确认主要瓶颈；
3. 为 value cache 和 key cache 分别设计 Triton reference kernel，先与 PyTorch 路径逐元素对照，再接入单 token decode；
4. 将 key low/high bits 的存储布局和 metadata 设计固定下来，明确 page table、channel index、scale/min 的 stride；
5. 在单卡正确性稳定后再验证双 A100 的模型切分或多请求吞吐，不把双卡作为 kernel 正确性的前提；
6. 每个 kernel 或评测里程碑单独提交，保留 PyTorch reference 作为回归真值。
